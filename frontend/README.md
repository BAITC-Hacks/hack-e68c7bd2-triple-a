# Фронтенд «Круг»

Одна страница `index.html`: HTML, CSS и JavaScript без npm, сборки и внешних ресурсов. Форма подбора подрядчиков, карточки с объяснениями и адаптивная вёрстка. Бэкенд, фильтрация, ранжирование и генерация объяснений реализуются другими участниками команды.

## Запуск

Из корня проекта:

```sh
python3 -m http.server 4173 --bind 0.0.0.0 --directory frontend
```

На этом компьютере открыть <http://127.0.0.1:4173>. Другие участники той же локальной сети открывают `http://<LAN-IP-компьютера>:4173`; текущий адрес по Ethernet — <http://10.19.30.100:4173>. После смены сети или IP адрес нужно обновить. Терминал с сервером должен оставаться запущенным. Сервер раздаёт только папку `frontend`.

Для реального поиска должен работать бэкенд. Если страница недоступна с другого компьютера, проверьте, что устройства находятся в одной подсети, сеть допускает соединения между ними, а входящие подключения Python к порту `4173` разрешены в настройках системы.

## Подключение API

В начале `index.html` указано:

```html
<meta name="api-base-url" content="auto">
```

`auto` использует протокол и имя хоста открытой страницы с портом `8000`. Например, с <http://10.19.30.100:4173> запрос уйдёт на `http://10.19.30.100:8000/search`. Бэкенд на этом компьютере должен слушать `0.0.0.0:8000`, чтобы принимать запросы участников LAN.

Если бэкенд запущен на другом компьютере, замените `auto` на его доступный адрес, например `http://10.19.30.101:8000`. Пустой `content=""` отправляет запрос на `/search` текущего домена. Для сайта на HTTPS нужен бэкенд на HTTPS либо прокси на том же домене. Ключи API на фронтенде не нужны.

При разных адресах frontend/backend сервер должен разрешить CORS для адресов, по которым открывают страницу: `http://127.0.0.1:4173`, `http://localhost:4173` и `http://10.19.30.100:4173`. Нужны метод `POST`, заголовок `Content-Type` и preflight `OPTIONS`. При смене LAN-IP обновите разрешённый origin на бэкенде.

### Запрос

`POST /search`, `Content-Type: application/json`:

```json
{
  "city": "Алматы",
  "event_date": "2026-11-14",
  "event_type": "свадьба",
  "category": "Фотограф",
  "budget_kzt": 300000,
  "duration_hours": null,
  "language": null
}
```

- Даты: 23.09.2026–31.12.2026 включительно.
- Город: `Алматы`, `Астана`, `Зарубежье`.
- Формат: `свадьба`, `той`, `корпоратив`, `конференция`, `юбилей`, `день рождения` — значения совпадают с `event_formats` каталога бэкенда.
- Категории: согласованные 10 из frontend-промпта. Исходный CSV содержит больше категорий; список можно дополнить после согласования с командой.
- Бюджет и длительность: положительные целые числа. Необязательные поля без значения передаются как `null`.
- Языки отправляются как `русский`, `казахский`, `английский` — точно как в исходном CSV; подписи в интерфейсе с заглавной буквы. Контракт задаёт только тип `str`, поэтому эти значения нужно сохранить и на бэкенде.
- Бэкенд сравнивает форматы событий с каталогом напрямую, поэтому значения `event_type` отправляются на русском.

### Ответ

```json
{
  "status": "ok",
  "message": null,
  "results": [
    {
      "id": "c_042",
      "name": "Асель Фото",
      "category": "Фотограф",
      "city": "Алматы",
      "price_from_kzt": 250000,
      "explanation": "Свободна на 14 ноября, бюджет укладывается, есть портфолио свадебной съёмки.",
      "synthetic": false
    }
  ]
}
```

При `ok` отображаются ровно 1–3 полученные карточки в порядке сервера. `message` тоже показывается: сервер может объяснить, почему вариантов меньше трёх. Фронтенд не придумывает причины и не генерирует объяснения.

Для `no_category` / `no_match` сервер возвращает `results: []` и пояснение в `message`. Это обычные пустые состояния, отдельно от сетевой ошибки. `synthetic: true` отображается подписью «синтетический профиль для демо».

Время ожидания — 45 секунд. При сетевой ошибке, HTTP-ошибке, тайм-ауте или нарушении контракта есть повторный запрос. Во время поиска форма заблокирована. Строки сервера вставляются через `textContent`, поэтому HTML в имени или объяснении не исполняется.

## Проверка интеграции командой

1. Алматы, 14.11.2026, свадьба, фотограф, 300 000 ₸ — проверить карточки и порядок.
2. Астана, 14.11.2026, свадьба, флорист, 500 000 ₸ — проверить один результат и пояснение сервера.
3. Астана, 15.11.2026, свадьба, декоратор, 300 000 ₸ — проверить карточку и отметку «синтетический профиль для демо»: бэкенд дополняет каталог демонстрационным декоратором.
4. Алматы, 26.12.2026, корпоратив, ведущий, 100 000 ₸ — ожидается `no_match`.
5. Задать язык и длительность, затем убрать их — проверить числа и `null` в запросе.
6. Остановить API — проверить сообщение и повтор поиска; проверить ширину 375 px и широкий экран.

Сценарии основаны на исходном датасете; окончательный ответ зависит от реализации и данных бэкенда. Демопрофили и фиктивный поиск в рабочую страницу не встроены.

## Что проверено

В браузере с временным тестовым HTTP-сервером, который не входит в проект:

- Точный JSON запроса, числовые значения, язык и длительность, `null` после очистки пожеланий.
- 1, 2 и 3 карточки; порядок сервера, `message` при неполной подборке и отметка синтетического профиля.
- `no_category`, `no_match`, HTTP 422, некорректный JSON и некорректная структура ответа.
- Блокировка формы при загрузке, ошибка отключённого API и успешный повтор после его включения.
- HTML внутри объяснения отображается как текст.
- Обязательные поля, обе границы дат, запрет отрицательных и дробных чисел, раскрытие необязательного поля при ошибке.
- Карточки в ряд на 1440 px, в столбец на 375 px; отсутствие горизонтального скролла на 320 и 375 px.

Также проверена связка с настоящим бэкендом команды по LAN: страница `http://10.19.30.100:4173`, API `http://10.19.30.100:8000`. Запрос «Алматы / 14.11.2026 / свадьба / Фотограф / 300 000 ₸» возвращает и отображает 3 карточки. Для локальной проверки использованы встроенные офлайн-объяснения бэкенда без ключа OpenAI.

Бэкенд команды расположен в соседней папке `backend`; инструкции его запуска — в `backend/README.md`. Для доступа участников LAN запустите его с параметрами `--host 0.0.0.0 --port 8000`.
