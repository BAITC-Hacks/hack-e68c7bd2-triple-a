# Shabyt — frontend

Адаптивное приложение для подбора подрядчиков на React + TypeScript + Vite. Оформление основано на [`shabyt-design-package`](../shabyt-design-package/): логотип и иконка Shabyt, шрифт Manrope, светлая и тёмная палитры. HTML содержит оболочку приложения и подключение внешнего модуля; компоненты, логика и стили разделены.

## Запуск

Нужен Node.js `^20.19.0` или `>=22.12.0`.

```sh
cd frontend
npm install
npm run dev
```

Страница доступна по адресу [localhost:4173](http://localhost:4173). Порт фиксирован: если он занят, остановите предыдущий сервер. По умолчанию приложение отправляет поиск в локальный FastAPI через Vite proxy.

Для запуска интерфейса с работающим поиском без бэкенда:

```sh
npm run dev:catalog
```

Сервер также использует порт 4173. Поиск в этом режиме выполняется в браузере по обезличенному каталогу; интерфейс сообщает об этом над формой.

### Локальный бэкенд

В другом терминале из корня репозитория:

```sh
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m uvicorn main:app --host 127.0.0.1 --port 8000
```

На Windows активируйте окружение командой `.venv\Scripts\activate`. Бэкенд использует офлайн-объяснения, если ключ OpenAI не настроен. API-ключи относятся к серверной конфигурации и не должны попадать в переменные `VITE_*` или клиентский код. Подробности — в [`backend/README.md`](../backend/README.md).

## Поведение интерфейса

- Светлая, тёмная и системная темы переключаются в меню. Выбор сохраняется в `localStorage`; системная тема реагирует на изменение настройки устройства. Логотип, favicon и цвет браузерной панели следуют выбранной теме.
- Форма проверяет обязательные поля, диапазон дат и положительные целые числа. Ошибки связаны с полями, фокус переходит к первому неверному значению. Город при первом запуске не выбран.
- Язык и длительность находятся в дополнительных пожеланиях и отправляются как `null`, если не указаны.
- Результаты содержат до трёх карточек, объяснения, стартовую цену и отметку синтетического профиля. «Рекомендации» сохраняет порядок подбора, «По цене» сортирует найденные варианты по возрастанию стоимости.
- Загрузка показывает скелетоны и позволяет отменить поиск. Во время запроса поля заблокированы. Тайм-аут — 45 секунд; устаревшие ответы не перезаписывают новый поиск.
- Отсутствующая категория, отсутствие совпадений и ошибка загрузки имеют отдельные состояния. Повтор использует параметры последнего запроса; «Изменить параметры» возвращает к форме.
- Черновик восстанавливается после перезагрузки. «Сбросить» очищает поля, результаты и сохранённый черновик. Черновики прежней версии «Круг» переносятся в хранилище Shabyt. Отказ или повреждение `localStorage` не блокирует работу формы.
- Навигация обновляет активный пункт и поддерживает историю браузера. Мобильное меню закрывается при выборе ссылки, по Escape и при нажатии вне шапки.
- «Подрядчикам», «Помощь» и «Политика» открывают справочные диалоги. Диалоги поддерживают клавиатуру и возвращают фокус после закрытия.
- Элементы имеют состояния hover, active, focus и disabled; анимации учитывают `prefers-reduced-motion`. На узких экранах форма и результаты располагаются в одну колонку.

Карточки предназначены для сравнения. Просмотр отдельных профилей, контакты и бронирование не входят в текущий контракт. Данные о цене и занятости необходимо подтвердить перед заказом.

## Режимы поиска

### API

Обычный `npm run dev` отправляет `POST /api/search`; Vite перенаправляет его на `http://127.0.0.1:8000/search`. Такой же proxy доступен в обычном preview. Ошибка API отображается с возможностью повтора; приложение не переключается на каталог без изменения конфигурации.

Ответ проверяется во время выполнения: поддерживаются `ok`, `no_category` и `no_match`, до трёх уникальных карточек и необязательное сообщение. Строки сервера выводятся React как текст.

### Статический каталог

`VITE_SEARCH_MODE=catalog` включает поиск без сервера. Файл `public/data/contractors.json` загружается относительно базового пути приложения, проверяется и кэшируется до перезагрузки страницы. Ошибку загрузки можно повторить; отмена работает и во время загрузки данных.

Каталог содержит 69 обезличенных записей из `backend/data/hackathon-dataset-anonymized.jsonl` и `backend/synthetic_profiles.jsonl`. Из них 16 уже имеют признак `synthetic` в исходных данных. Сохраняются только поля, необходимые для поиска и отображения. При обновлении исходных наборов нужно также обновить JSON фронтенда.

Правила повторяют текущий бэкенд: город и категория, исключение занятых дат, ограничение бюджета, формат события, язык и длительность. Среди прошедших фильтры выше располагаются варианты с ценой ближе к бюджету; учитываются язык и совпадения слов описания с запросом, при равенстве используется идентификатор. Выдаются первые три записи. Объяснения формируются по фактам каталога без вызова серверного ИИ; отсутствие отметки о занятости не означает подтверждённое бронирование.

## Настройки окружения

Для локальных изменений скопируйте `.env.example` в `.env.local` и перезапустите Vite.

| Переменная | Обычный режим | Назначение |
| --- | --- | --- |
| `API_PROXY_TARGET` | `http://127.0.0.1:8000` | Адрес бэкенда для proxy Vite |
| `VITE_API_BASE_URL` | `/api` | Путь API или полный публичный адрес без `/search` в конце |
| `VITE_SEARCH_MODE` | `api` | `api` для HTTP-запросов; `catalog` для поиска в браузере |
| `VITE_BASE_PATH` | `/` | Базовый путь публикации |

`.env.pages` задаёт `VITE_SEARCH_MODE=catalog` и `VITE_BASE_PATH=/hack-e68c7bd2-triple-a/`. Переменные окружения процесса имеют приоритет над файлами Vite. `dev:catalog` переопределяет базовый путь на `/` для удобства локальной разработки.

`VITE_API_BASE_URL` принимает путь `/api`, `/` для same-origin `/search` или абсолютный HTTP(S)-адрес. Значение `auto` использует хост страницы с портом 8000 и подходит только для соответствующим образом настроенной локальной сети. Для HTTPS-сайта нужен доступный HTTPS-бэкенд. При обращении к другому origin сервер должен разрешать его через CORS.

Все значения `VITE_*` становятся частью клиентской сборки и не должны содержать секреты. После изменения настроек опубликованный сайт нужно пересобрать.

### Контракт запроса

```json
{
  "city": "Алматы",
  "event_date": "2026-11-14",
  "event_type": "свадьба",
  "category": "Фотограф",
  "budget_kzt": 300000,
  "duration_hours": null,
  "language": null
}
```

Форматы и языки передаются на русском строчными буквами. Текущий набор данных и форма рассчитаны на даты 23.09.2026–31.12.2026. Контракты находятся в `src/types/search.ts`.

## Публикация в GitHub Pages

Адрес после успешного развёртывания: [baitc-hacks.github.io/hack-e68c7bd2-triple-a](https://baitc-hacks.github.io/hack-e68c7bd2-triple-a/).

1. Владелец репозитория или участник с правом управления Pages открывает **Settings → Pages → Build and deployment** и выбирает **Source: GitHub Actions**. Одного права отправлять коммиты недостаточно для изменения настройки Pages.
2. Workflow [`.github/workflows/pages.yml`](../.github/workflows/pages.yml) проверяет фронтенд, выполняет сборку Pages и публикует `frontend/dist`. Он запускается при изменениях фронтенда в `main` или вручную через **Actions → Deploy Shabyt to GitHub Pages → Run workflow**.
3. Успешное завершение задания deploy подтверждает публикацию. Проверьте указанный в нём URL, тему, загрузку каталога и поиск на телефоне и компьютере.

GitHub Pages обслуживает HTML, CSS, JavaScript и другие статические файлы. Наличие папки `backend` в репозитории не запускает Python/FastAPI. Поэтому первая публикация настроена на самостоятельный режим `catalog`.

Для подключения серверного поиска сначала разместите бэкенд на отдельном сервисе с публичным HTTPS-адресом. Настройте CORS для `https://baitc-hacks.github.io`, затем в **Settings → Secrets and variables → Actions → Variables** задайте:

| Переменная репозитория | Значение |
| --- | --- |
| `VITE_SEARCH_MODE` | `api` |
| `VITE_API_BASE_URL` | HTTPS-адрес бэкенда, например `https://api.example.com` |

После этого повторите workflow. Без `VITE_SEARCH_MODE` workflow использует `catalog`; адрес API в этом режиме не требуется. Секреты серверного ИИ остаются на стороне хостинга бэкенда.

## Проверка изменений

Перед отправкой изменений выполните `npm run typecheck`, `npm test` и нужную команду сборки. Тесты покрывают контракт API, фильтрацию и ранжирование каталога, валидацию, черновик, темы, отмену, тайм-аут, повтор поиска, пустые состояния, сортировку, диалоги и навигацию.

Для ручной проверки: Алматы → 14.11.2026 → Свадьба → Фотограф → 300000 ₸. Сравните сортировки, измените тему и перезагрузите страницу. Для состояния без совпадений задайте бюджет 1 ₸; для отсутствующей категории выберите Зарубежье → Флорист. Проверьте сброс формы, управление с клавиатуры, мобильное меню и отсутствие горизонтальной прокрутки на узком экране. В API-режиме дополнительно проверьте ошибку и повтор после остановки и восстановления бэкенда.
