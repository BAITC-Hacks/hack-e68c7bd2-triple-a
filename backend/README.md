# Backend — умный подбор подрядчиков

FastAPI-сервис для кейса #79-lite. Отдаёт до 3 карточек подрядчиков с LLM-объяснением
по запросу (город, дата, тип мероприятия, категория, бюджет, опционально язык/длительность).

## Быстрый старт

```bash
cd backend
python3 -m venv venv && source venv/bin/activate   # опционально
pip install -r requirements.txt

# без ключа тоже работает — llm_explain.py уходит в offline-фолбэк
export OPENAI_API_KEY=sk-...        # опционально, для реальных LLM-объяснений

uvicorn main:app --reload
```

Проверка: `curl http://127.0.0.1:8000/health` → `{"status":"ok","catalog_size":69}`.

## Данные

- `data/hackathon-dataset-anonymized.jsonl` — 66 реальных профилей, сконвертированы из
  выданного `hackathon_dataset_anonymized_.csv` (поля `categories`/`event_formats`/
  `languages`/`busy_dates` разбиты в списки).
- `synthetic_profiles.jsonl` — 3 придуманных профиля (`synthetic: true`) для категорий,
  где в Астане не было ни одного реального подрядчика: Декоратор, Инструменталист,
  Ведущий церемонии. Подгружаются автоматически при старте, id с префиксом `SYN-`.
- Оба файла грузятся в `data_loader.py` один раз при старте и кэшируются в памяти
  (`GET /health` покажет итоговый размер каталога).

## Эндпоинт

`POST /search`

```json
{
  "city": "Алматы",
  "event_date": "2026-11-14",
  "event_type": "свадьба",
  "category": "Фотограф",
  "budget_kzt": 300000,
  "duration_hours": null,
  "language": null
}
```

Ответ:

```json
{
  "status": "ok",
  "message": null,
  "results": [
    {
      "id": "HK-91112",
      "name": "Мэгуми Фушигуро",
      "category": "Фотограф",
      "city": "Алматы",
      "price_from_kzt": 300000,
      "explanation": "...",
      "synthetic": false
    }
  ]
}
```

`status`: `"ok"` (есть карточки) / `"no_category"` (в этом городе нет такой категории
вообще) / `"no_match"` (категория есть, но фильтры отсеяли всех — `message` объясняет
причину: сколько заняты на дату / не тянут бюджет / не берут формат / язык / длительность).

## Как это устроено

1. **`data_loader.py`** — читает jsonl (основной + synthetic), валидирует обязательные
   поля, поднимает `DatasetError` при пустом/битом файле (main.py вернёт 500 с понятным
   текстом, а не молчаливо упадёт).
2. **`filters.py`** — сначала проверяет, есть ли категория в городе вообще
   (`no_category`), потом фильтрует по дате/бюджету/формату/языку/длительности и
   возвращает причины отказа для тех, кто не прошёл (`no_match` с объяснением).
3. **`ranking.py`** — чистая арифметика, без ML и без LLM: цена ближе к бюджету снизу
   → выше, +бонус за язык, +бонус за пересечение ключевых слов запроса с `description`.
   При равенстве очков сортировка по `id` — гарантирует детерминизм при повторном запуске.
4. **`llm_explain.py`** — `generate_explanation(profile, match_reasons)`. Реальный вызов
   OpenAI Chat Completions (`gpt-4o-mini` по умолчанию, меняется через
   `OPENAI_EXPLAIN_MODEL`) с системным промптом, который явно запрещает шаблонные фразы
   ("отличный выбор для вашего мероприятия" и т.п.) и требует опираться на конкретные
   факты (цена/дата/язык/ключевые слова). Если ключа нет или API недоступен — offline
   фолбэк собирает предложение из тех же фактов (детерминированно по `id`), чтобы демо
   не падало без интернета на сцене.
5. **`main.py`** — Pydantic-валидация входа (формат даты, непустые поля), сборка ответа,
   обработка ошибок датасета как 500 с текстом, а не трейсбеком.

## Допущение про город "Зарубежье"

В датасете есть подрядчики с `city = "Зарубежье"`. Мы **не** подмешиваем их в выдачу по
запросу `"Алматы"`/`"Астана"` — только явный запрос `city = "Зарубежье"` их найдёт.
Логика в `filters.city_matches()`, меняется в одном месте, если продукт решит иначе.

## Что проверено вручную (см. три обязательных сценария из ТЗ)

- Плотная категория на осеннюю дату: `Фотограф / Алматы / 2026-11-14` → 3 карточки,
  ранжирование по близости цены к бюджету видно в `explanation`.
- Тот же запрос на другую дату (`2026-09-23`) → другой состав/порядок карточек — видно,
  что дело в занятости.
- Редкая категория: `Инструменталист / Астана` — раньше был `no_category`, теперь есть
  synthetic-профиль, явно помечен `"synthetic": true` в ответе.
- Пустой результат с бюджетом 10 000 тг → `status: "no_match"`, текст объясняет: у скольких
  цена выше бюджета, скольких заняты на дату и т.д.
- Повторный запрос с теми же параметрами → тот же порядок id (детерминизм, ranking.py
  сортирует по `(-score, id)`).

## Известные ограничения / что дальше

- `event_type` матчится точной строкой против `event_formats` контрактора — если фронт
  пришлёт синоним ("свадебное торжество" вместо "свадьба"), матч не сработает. Нужен
  общий словарь форматов между фронтом и бэком (см. контракт в 1_BACKEND.md).
  Отдельного эндпоинта со списком допустимых категорий/форматов пока нет — фронт должен
  использовать те же строки, что в датасете (см. `hackathon_dataset_preview.html`).
- Keyword-бонус в ранжировании — наивный токен-матч (без стемминга/синонимов), сознательно
  простой, чтобы оставаться объяснимым и детерминированным без ML.

## Валидация API

`event_date` принимается только в диапазоне календаря датасета: `2026-09-23` — `2026-12-31`.
`budget_kzt` и переданный `duration_hours` должны быть больше нуля.
Offline-объяснения детерминированы между перезапусками процесса.
