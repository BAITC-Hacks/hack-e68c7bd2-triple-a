Дата: 23 сентября 2026. Основа: последний загруженный ZIP `(2)`, не более ранний backend-архив.

Это не копия алгоритма и не замена полной проверки типов. 150 ожидаемых ответов получены от FastAPI TestClient; сравниваются статус и порядок ID, а не стилистика объяснений.

## Backend: охват

Проверены `/health`, `/search`, `/api/search`, метаданные и обычный контракт. Проверены город, категория, формат, бюджет, язык, длительность, точные границы, `max_hours=null`, статусы `ok/no_category/no_match`, меньше трёх результатов, синтетические метки, повторяемость и разные даты. Отдельный тест перебирает все занятые даты каждого из 69 профилей и проверяет исключение занятого кандидата. Дополнительно проверяются 150 комбинаций условий.

Проверены невозможные и выходящие за диапазон даты, базовая ISO-запись `20261114`, ISO-неделя, нулевые/отрицательные/дробные/логические значения чисел, пустые поля, неожиданные поля, дубли ID, повреждённый JSON, отсутствующий календарь, 503 при сломанном каталоге и отсутствие внутренних путей в публичном ответе.

LLM-успех, ошибка, тайм-аут и сохранение порядка при параллельном завершении проверялись **на mock-клиенте**. Реальных API-вызовов и расходов не было. SDK OpenAI в данной среде не был доступен для реального вызова. Наличие ключа в `/health` — конфигурация, а не доказательство доступности провайдера.

Для одного сервера отдельно запущен тест с **минимальной статической HTML/JS-фикстурой**, не настоящим frontend/dist: GET `/` отдаёт HTML, `/assets/app.js` — JavaScript MIME, `/api/search` и `/api/health` не перекрываются static mount.

## Браузер: что и как проверялось

Chromium был запущен через Playwright. Интерфейс собран из изменённых production TS/TSX и CSS, но локальный диагностический стенд использовал доступный **React 18.2**, а не проектный React 19.3. Из-за ограничений среды страница монтировалась через `set_content`, без навигации на сетевой адрес. `fetch` заменён адаптером к **реальному FastAPI TestClient**; ошибки/задержки и повреждённый ответ задавались отдельно. Storage — в памяти, плюс отдельный тест с заблокированным localStorage. Шрифтовые npm-ресурсы не загружались; снимки используют системный fallback. Сам диагностический React/runtime не включён в архив.

Это проверяет компоненты, взаимодействия и вёрстку, **но не является полноценным end-to-end тестом Vite, браузерного HTTP/CORS или production-развёртывания**.

Пройдены: старт, заполнение и ошибки формы, фокус первого поля, исправление ошибок демо-кнопкой, 17 категорий, реальные результаты демо, обе сортировки, раскрытие профиля, разные даты, синтетический профиль и объяснение малого количества, пустая категория, пустая выдача, ошибки сети/503/повреждённого ответа, повторный запрос, блокировка дублирующих действий, отмена, игнорирование позднего ответа и клиентский тайм-аут. HTML из профиля не исполняется. Проверены тёмная тема, native dialog и Escape, мобильное меню и возврат фокуса. Ошибок JS в этих сценариях не зарегистрировано.

Проверены ширины **1440, 1024, 768, 390, 375, 320 px**: горизонтального переполнения в проверенных состояниях нет. Карточки результатов дополнительно проверены на 390 и 320 px. Снимки — `docs/desktop-light.png`, `desktop-dark.png`, `mobile-light.png`, `desktop-results.png`.

## Что не подтверждено

**`npm ci`, полный `npm run build`, TypeScript typecheck и Vitest завершить не удалось:** среда не разрешала DNS к `registry.npmjs.org` (`EAI_AGAIN`). Поэтому нельзя утверждать, что пакет прошёл финальную сборку с точными зависимостями из lockfile. В исходниках сохранены зависимости и lockfile последнего архива. До демо необходимо выполнить `CHECK_WINDOWS.bat` на машине с доступом к npm/PyPI.

Не выполнялись: npm audit/полный аудит безопасности, нагрузочные испытания, реальные OpenAI/NVIDIA-запросы, запуск `.bat` на Windows, Safari/Firefox, реальный мобильный аппарат, деплой на Pages или публичный сервер. Проверка XSS/валидации не означает отсутствия всех уязвимостей. Prompt guard не гарантирует идеальную фактическую точность LLM; перед демо ответы внешней модели нужно проверить отдельно.

Нет реального бронирования или проверки фактической занятости подрядчика: используется календарь датасета. Доступность за пределами его 100 дней намеренно не предполагается. API возвращает контролируемую ошибку валидации.

## Исправленные дефекты

1. Отсутствовали семь категорий в форме; теперь доступны все 17 из текущего датасета.
2. Неканоническая ISO-запись могла пройти date.fromisoformat, но не совпасть со строками busy_dates. Теперь дата строго `YYYY-MM-DD` и внутри диапазона.
3. При одном/двух результатах не объяснялось, почему их меньше трёх. Теперь есть количество и конкретные причины исключения остальных.
4. Порядок перечисления причин зависел от множества; теперь он фиксирован.
5. Улучшена проверка каталога: дубли, отсутствующие календари и неверные типы не превращаются в ложную доступность.
6. Неправильный/медленный ответ LLM приводит к явно отмеченному резервному объяснению; карточки обрабатываются параллельно с пределом ожидания, порядок сохраняется.
7. Демо-кнопки больше не оставляют старые ошибки полей после заполнения валидных параметров.
8. `/` без сборки ведёт на `/docs`, а с готовой сборкой показывает сайт. Добавлены API-алиасы, запуск одного процесса и проверка static MIME на фикстуре.
9. Добавлена граница ошибок React вместо пустого экрана при перехватываемой ошибке рендера. Она не может исправить сломанную сборку/загрузку JS — для этого запуск останавливается при ошибках npm/build.
