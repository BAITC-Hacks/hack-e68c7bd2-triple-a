# Shabyt — люди для вашего события

Shabyt / Шабыт помогает подобрать до трёх подрядчиков по городу, дате, формату события, категории, бюджету и дополнительным пожеланиям. Проект команды Triple-A для хакатона: адаптивный интерфейс на React + TypeScript + Vite и отдельный Python/FastAPI-бэкенд.

## Что находится в репозитории

| Папка | Содержимое |
| --- | --- |
| [`frontend/`](frontend/) | Приложение, компоненты, отдельные CSS-файлы, тесты и каталог для статической публикации |
| [`backend/`](backend/) | API поиска, фильтрация, ранжирование и объяснения результатов |
| [`shabyt-design-package/`](shabyt-design-package/) | Исходный дизайн-пакет: спецификация, макеты, логотипы и иконки |
| [`.github/workflows/pages.yml`](.github/workflows/pages.yml) | Проверка, сборка и публикация фронтенда в GitHub Pages |

Фронтенд использует оформление Shabyt, шрифт Manrope и светлую, тёмную или системную тему. Форма сохраняет черновик, результаты можно сортировать по рекомендации или цене. Навигация, мобильное меню, справочные диалоги, отмена и повтор поиска работают с клавиатуры и на сенсорных устройствах.

## Быстрый запуск

Нужен Node.js `^20.19.0` или `>=22.12.0`.

```sh
cd frontend
npm install
npm run dev
```

Откройте [localhost:4173](http://localhost:4173). В этом режиме поиск обращается к локальному бэкенду на порту 8000. Его запуск описан в [документации фронтенда](frontend/README.md#локальный-бэкенд) и [документации API](backend/README.md).

Для работы без Python-сервера остановите предыдущий Vite-сервер и запустите:

```sh
npm run dev:catalog
```

Этот режим выполняет поиск в браузере по обезличенным данным из репозитория и явно обозначен в интерфейсе. Каталог содержит 69 профилей: 66 из основного набора и 3 дополнительных. У 16 профилей в исходных данных стоит признак `synthetic`; эти карточки отмечены в интерфейсе. Фильтры и порядок рекомендаций соответствуют правилам бэкенда, объяснения составляются из фактов каталога без серверного ИИ.

## Проверка и сборка

Из папки `frontend`:

```sh
npm run typecheck
npm test
npm run build:pages
npm run preview:pages
```

Предпросмотр сборки для Pages: [localhost:4174/hack-e68c7bd2-triple-a/](http://localhost:4174/hack-e68c7bd2-triple-a/). Обычная сборка для размещения в корне сайта создаётся командой `npm run build`.

## GitHub Pages

Адрес после успешного включения и развёртывания: [Shabyt на GitHub Pages](https://baitc-hacks.github.io/hack-e68c7bd2-triple-a/).

Для первой публикации владелец репозитория или участник с правом управления Pages должен выбрать **Settings → Pages → Build and deployment → Source → GitHub Actions**. Затем при необходимости запустить **Actions → Deploy Shabyt to GitHub Pages → Run workflow**. После настройки workflow публикует изменения фронтенда из `main`; перед публикацией выполняются тесты и сборка.

По умолчанию Pages использует режим `catalog` и путь `/hack-e68c7bd2-triple-a/`. GitHub Pages размещает статические файлы и не запускает FastAPI из папки `backend`. Для серверного режима сначала разместите бэкенд отдельно по публичному HTTPS-адресу, разрешите origin сайта в CORS, затем задайте переменные репозитория `VITE_SEARCH_MODE=api` и `VITE_API_BASE_URL=https://адрес-бэкенда` и повторите workflow. Подробнее — в [инструкции по публикации](frontend/README.md#публикация-в-github-pages).

Проект показывает соответствие данным каталога. Контакты, подтверждение занятости, окончательная стоимость и бронирование не входят в текущий интерфейс и контракт API.
