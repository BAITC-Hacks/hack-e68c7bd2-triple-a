# Shabyt — люди для вашего события

**Shabyt / Шабыт** — сервис умного подбора подрядчиков для мероприятий.  
Пользователь задаёт параметры события, а система возвращает до трёх подходящих вариантов и объясняет, **почему каждый конкретный подрядчик соответствует запросу**.

Проект команды **Triple-A**, разработанный в рамках HackAlem AI Hackathon.

---

## О проекте

Поиск подрядчика для мероприятия — это не только сортировка каталога по цене. Важно учитывать одновременно дату, город, формат события, бюджет, язык, длительность работы и особенности конкретного исполнителя.

Shabyt превращает эти параметры в короткую и понятную подборку.

Пользователь указывает:

- город;
- дату мероприятия;
- тип события;
- категорию подрядчика;
- бюджет;
- при необходимости — язык и длительность.

Система фильтрует каталог, исключает неподходящие варианты, ранжирует оставшихся кандидатов и возвращает **до трёх рекомендаций**.

Главная особенность Shabyt — **объяснимость результата**. Вместо безличного рейтинга пользователь получает конкретное объяснение, основанное на данных профиля: специализации, формате мероприятий, стоимости, языке, длительности и других релевантных характеристиках.

---

## Возможности

- подбор до 3 наиболее релевантных подрядчиков;
- фильтрация по городу, дате, категории и формату события;
- учёт бюджета;
- дополнительные фильтры по языку и длительности;
- исключение занятых на выбранную дату подрядчиков;
- детерминированный порядок рекомендаций;
- персонализированное объяснение для каждой рекомендации;
- отдельные состояния для отсутствия категории и отсутствия подходящих кандидатов;
- корректная обработка случаев, когда найдено меньше трёх вариантов;
- маркировка синтетических профилей;
- адаптивный интерфейс для desktop и mobile;
- светлая, тёмная и системная темы;
- локальный catalog-режим для демонстрации без запущенного API.

## Как работает Shabyt

```text
Параметры события
        ↓
Валидация запроса
        ↓
Фильтрация каталога
        ↓
Проверка доступности
        ↓
Проверка бюджета и условий
        ↓
Детерминированное ранжирование
        ↓
До 3 подрядчиков
        ↓
Объяснение каждой рекомендации
        ↓
Карточки результатов
```

Если подходящих кандидатов нет, пользователь не получает пустой экран. Shabyt объясняет причину: например, нужной категории нет в выбранном городе либо существующие подрядчики не прошли условия поиска.

## Интерфейс

Интерфейс построен вокруг быстрого сравнения рекомендаций.

Каждая карточка показывает:

**имя → категорию → город → стоимость → причину рекомендации**

Блок **«Почему подходит»** является центральной частью карточки: объяснения используют конкретные характеристики подрядчика вместо универсальных рекламных формулировок.

Интерфейс адаптирован под мобильные устройства, поддерживает клавиатурную навигацию и сенсорное управление. Форма сохраняет черновик запроса, а результаты можно сортировать по рекомендации или стоимости.

## Быстрый запуск

### Frontend

Требуется Node.js:

```text
^20.19.0 или >=22.12.0
```

Установите зависимости и запустите dev-сервер:

```bash
cd frontend
npm install
npm run dev
```

После запуска приложение доступно по адресу:

```text
http://localhost:4173
```

В стандартном режиме frontend отправляет поисковые запросы локальному backend на порту `8000`.

Инструкции по его запуску находятся в:

- [`frontend/README.md`](frontend/README.md)
- [`backend/README.md`](backend/README.md)

## Автономный demo-режим

Для демонстрации интерфейса без Python/FastAPI предусмотрен catalog-режим.

```bash
cd frontend
npm install
npm run dev:catalog
```

В этом режиме поиск выполняется непосредственно в браузере по обезличенному каталогу проекта.

Catalog-режим предназначен прежде всего для демонстрации frontend: фильтрация и порядок рекомендаций воспроизводятся локально, а объяснения формируются из фактов профилей без обращения к серверному AI.

## Демо-сценарии

Для проверки основных возможностей рекомендуем протестировать несколько разных сценариев.

### 1. Популярная категория

Например:

```text
Город: Алматы
Категория: Фотограф
Тип события: Свадьба
```

Ожидаемый результат — короткая подборка кандидатов с различающимися персональными объяснениями.

### 2. Редкая категория

Например:

```text
Категория: Флорист
```

Система должна корректно работать даже при небольшом количестве профилей и не создавать искусственные результаты.

### 3. Нет подходящих вариантов

Используйте дату, бюджет или другие ограничения, исключающие доступных кандидатов.

Вместо пустого результата интерфейс должен объяснить, почему подборка не сформирована.

## Данные

Проект работает с обезличенным каталогом подрядчиков.

Профили содержат данные, необходимые для подбора, включая:

- категорию;
- город;
- минимальную стоимость;
- поддерживаемые форматы мероприятий;
- языки;
- максимальную длительность работы;
- занятые даты;
- описание профиля;
- технические признаки происхождения данных.

Синтетические профили явно маркируются в интерфейсе и не маскируются под обычные записи.

## GitHub Pages

Frontend может быть опубликован через GitHub Pages:

https://baitc-hacks.github.io/hack-e68c7bd2-triple-a/

Для первой публикации:

**Settings → Pages → Build and deployment → Source → GitHub Actions**

После этого при необходимости:

**Actions → Deploy Shabyt to GitHub Pages → Run workflow**

Workflow проверяет и собирает frontend перед публикацией изменений из `main`.

По умолчанию GitHub Pages использует статический `catalog`-режим.

> GitHub Pages не запускает FastAPI.

Для полноценного API-режима backend необходимо разместить отдельно по публичному HTTPS-адресу, настроить CORS и определить переменные репозитория:

```text
VITE_SEARCH_MODE=api
VITE_API_BASE_URL=https://your-backend.example
```

## Ограничения

Shabyt является системой **подбора и объяснения рекомендаций**, а не платформой бронирования.

В текущую версию не входят:

- бронирование подрядчика;
- оплата;
- обмен сообщениями;
- проверка контактных данных;
- подтверждение заказа;
- подтверждение окончательной стоимости вне данных каталога.

Результат показывает соответствие подрядчика параметрам запроса на основании доступных данных каталога.
